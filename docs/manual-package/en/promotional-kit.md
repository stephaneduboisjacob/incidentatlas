# Promotional kit

All copy below describes the current early-development build. Keep the stated scope and limitations when adapting it; do not promise unsupported connectors, automatic root-cause discovery, or production readiness.

## Product description

**IncidentAtlas is a self-hostable operational change recorder for incident investigations.** It builds a reviewable timeline of what changed around an outage, links suggestions to source events, and leaves causal decisions to the people investigating.

## Landing page

### Headline

**When production breaks, see what changed.**

### Subheading

Reconstruct the operational timeline around an outage with compact, privacy-minded change records and evidence-linked, explainable suggestions. Keep the data in your own installation.

### Supporting points

- Follow changes across Linux services and supported host sources.
- Review event time, resource, before/after state, and integrity digest in one timeline.
- See why an event is suggested and inspect the linked evidence.
- Preserve investigation notes and mark a hypothesis as confirmed only through human review.
- Run a bounded collector queue and choose dry-run, local, or connected operation.
- Self-host with PostgreSQL and a local artifact store; AI is not required for deterministic correlation.

## Launch post

We are building IncidentAtlas: a self-hostable change recorder for the difficult hours after an outage. It brings supported operational changes into a timeline, explains why some events may be relevant, and links each suggestion back to evidence. The goal is a faster, more reliable reconstruction—not another stream of logs. The project is in early development, and the first focus is a small Linux/systemd/Docker/Nginx workflow.

## Editorial guidance

Say **hypothesis**, **possible contributor**, **supporting evidence**, and **human-confirmed**. Avoid “AI found the root cause,” guaranteed recovery-time claims, and claims that every planned connector is already available. State that the current build is early development and that the license is still pending before redistributing it.
