# Безопасность и конфиденциальность

## Принцип сбора

IncidentAtlas предназначен для хранения компактных изменений состояния, необходимых для реконструкции инцидента. Перед подключенной передачей коллектор применяет редактирование чувствительных данных. Текущие источники: структурированные события жизненного цикла systemd, метаданные жизненного цикла контейнеров Docker при явном включении и хеши явно настроенных файлов Nginx. Коллектор не отправляет текст сообщений журнала, переменные среды Docker, журналы контейнеров, содержимое файлов Nginx, текст SQL или параметры запросов, данные приложения, приватные ключи или исходный код репозитория.

Это цель проектирования, а не гарантия безопасности каждого хоста или пользовательского источника. Проверьте вывод `dry-run`, ограничьте источники и при необходимости добавьте локальные шаблоны для чувствительных идентификаторов.

## Классификация данных

| Класс | Примеры | Обработка |
| --- | --- | --- |
| PUBLIC | Опубликованная версия ПО | Можно распространять |
| OPERATIONAL | Статус сервиса, дайджест образа, срок сертификата | Операционная запись под контролем организации |
| SENSITIVE | Имена хостов, пути, идентификаторы пользователей | Минимизировать, ограничивать доступ, применять сроки хранения |
| SECRET | Пароли, токены, приватные ключи, cookie | Редактировать локально; намеренно не сохранять |
| PROHIBITED | Данные клиентов, строки таблиц, содержимое приватных ключей | Не собирать |

## Меры для операторов

- Сначала используйте `dry-run`, затем `local` и только потом `connected`.
- Запускайте агент от выделенного пользователя без привилегий и давайте только необходимый доступ. Не включайте Docker, если вы не принимаете привилегии, эквивалентные root.
- Используйте HTTPS с проверкой сертификата; не отключайте проверку TLS.
- Защищайте токены первоначальной настройки, учетные данные коллектора, `.env`, резервные копии и хранилища данных.
- Оставляйте PostgreSQL закрытым, а публичный API размещайте за HTTPS.
- Проверьте метаданные событий и пути файлов до включения сбора.
- Шифруйте резервные копии, копируйте их за пределы хоста и проверяйте восстановление. Подключайте сбор с наблюдаемого хоста лишь после проверки внешних копий и процедур восстановления.
- Внимательно задавайте сроки хранения и юридические запреты. Подтвержденное сокращение срока может асинхронно удалить свидетельства.

## Доступ, целостность и ограничения

Запросы API ограничивают данные организацией. Учетные данные коллекторов хранятся в виде хешей и могут быть отозваны. У событий есть SHA-256 дайджесты; артефакты адресуются по дайджесту и проверяются при очистке и резервном копировании. Дайджест позволяет обнаружить некоторые изменения сохраненных байтов, но не доказывает достоверность события с скомпрометированного хоста. Часы хоста могут идти неверно, коллектор может быть отключен, а отсутствие события не доказывает отсутствие изменения.

Аналитика продукта по умолчанию отключена. В текущем MVP нет полной панели управления учетными записями, внешнего поставщика идентификации, источника событий PostgreSQL, полных снимков конфигурации, автоматических внешних резервных копий или причинного анализа с помощью ИИ. Подробные предположения и способ сообщить об уязвимости описаны в `docs/threat-model.md`, `docs/privacy.md` и `SECURITY.md`.
